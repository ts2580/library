# Bookshelf 3.3.1

중고 재고 일괄 갱신에서 오프라인 지점 재고 조회가 누락되는 문제 수정.

## 변경 내용

- 상품 조회 응답의 `spaceUsed.itemCount`가 0이거나 없어도 지점 재고 API를 독립적으로 조회하도록 수정. 상품 조회 결과가 비어 있는 경우에도 전체 재고 검색의 지점 조회 수행.
- 직배송 전용 검색의 조회 범위 유지. 지점 상세를 확인하지 못한 결과의 저장 차단 및 호출 제한 중단 정책 유지.
- 실제 응답에서 지점 재고가 있어도 요약 재고 수가 0인 경우를 회귀 검사에 추가. PC·모바일 화면에서 지점 재고 저장 및 집계 반영 검사 추가.

## 기존 설치 업데이트

`3.3.1` 이미지 발행을 확인한 뒤 기존 `.env`와 실제 데이터 볼륨 이름을 유지하여 웹·워커를 함께 교체합니다.

```sh
BOOKSHELF_IMAGE=trstyq/bookshelf:3.3.1 docker compose -f docker-compose.release.yml pull
BOOKSHELF_IMAGE=trstyq/bookshelf:3.3.1 docker compose -f docker-compose.release.yml up -d
```

DB 스키마 버전 4를 유지하며 새 마이그레이션은 없습니다. DB·표지·업로드·백업은 기존 볼륨을 그대로 사용합니다.

일괄 갱신은 워커가 작업을 시작할 때 현재 계정의 이전 재고를 삭제하고 새 결과를 저장합니다. 웹·워커는 같은 코드와 DB 경로를 사용해야 합니다.

## 실제 API 검증

실제 알라딘 응답과 별도 워커 프로세스를 사용한 임시 DB 검사에서, 같은 ISBN의 저장 결과가 수정 전 직배송 1건에서 수정 후 직배송 포함 45개 지점·재고 67건으로 변경됨을 확인했습니다. 수정 후 한 권 처리 시간은 약 15초였습니다. 재고 수는 조회 시점에 따라 바뀔 수 있습니다.

기존 로컬 DB의 도서·재고는 변경하지 않았으며, 이 기록은 운영 인스턴스의 갱신 완료를 의미하지 않습니다.
