# Java → Next.js 기능 대조 점검

> ca2까지의 구현·검증 당시 기록입니다. 아래 `next/`·Java 실행 경로와 결과는 해당 시점 기준이며, ca3 현재 실행·검증은 [루트 전환 기록](CA3_ROOT_LAYOUT.md)을 참고하세요.

2026-10-17 KST, `feat/nextjs-migration` 로컬 소스 기준입니다. Java의 컨트롤러·서비스·Thymeleaf·브라우저 JavaScript를 기준으로 기능을 대조했습니다. 기존 단위·통합 50건과 브라우저 28건이 통과해도 실제 표지 다운로드와 Java 백업 형식은 실패하는 것을 확인했습니다.

## 직접 추가 실패 원인

`/books → 책 직접 추가`에서 실제 알라딘 항목을 선택하면 표지 다운로드 중 `ERR_INVALID_IP_ADDRESS: Invalid IP address: undefined`가 발생했습니다. HTTP 클라이언트가 DNS 조회에 `all=true`를 지정하는데, 커스텀 조회 함수가 주소 배열 대신 문자열을 반환했습니다. 반환 형식을 요청 옵션에 맞게 수정했습니다. 사설 주소 차단과 검증한 주소로만 연결하는 정책은 유지했습니다.

실제 알라딘의 `장송의 프리렌` 검색 결과 1권을 격리한 임시 DB에 등록하고, 실제 이미지 다운로드·WebP 저장·도서와 권의 표지 참조를 확인했습니다. 자동 표지 다운로드만 실패할 때는 권 등록을 유지하고 원본 URL을 보존하며, 화면에 실패한 표지 수와 재생성 방법을 알립니다. 직접 업로드한 잘못된 파일이나 사용자가 지정한 잘못된 URL은 계속 오류로 처리합니다.

## 검증 경계

### 원본 정리 상태 표시 수정

프로필이 브라우저의 최초 GET 요청에만 의존해 `원본 데이터 상태를 확인하고 있습니다.`에 머물 수 있었습니다. 읽기 전용으로 확인한 실제 정리 상태는 `CLEANED`였으며, 기존 원본 DB·표지가 없었습니다. 서버에서 초기 상태를 전달해 브라우저 JavaScript가 실행되지 않아도 완료·차단 사유를 표시하도록 수정했습니다. `상태 다시 확인` 버튼, 15초 조회 제한, HTTP 오류·잘못된 응답 안내와 재시도를 추가했습니다.

수정 전 초기 렌더링 회귀 3건 실패를 확인했고, 수정 후 소스 검사·단위/통합 **89/89**, 프로덕션 빌드, 관련 브라우저 **12/12**(데스크톱 6·모바일 6)를 통과했습니다. 브라우저에서는 JavaScript 비활성 상태의 초기 표시, 조회 실패·시간 초과·재시도, 확인 취소·완료 표시와 관리자 권한을 확인했습니다. 실제 사용자 원본은 삭제하지 않았습니다. 삭제 서비스 검사는 임시 파일을 사용했고, 브라우저 삭제 응답은 모의 응답으로 처리했습니다.

빌드와 브라우저 검사는 실행 중인 개발 서버와 분리한 소스 사본에서 진행합니다. SQLite·표지·계정·웹·워커는 테스트 실행마다 임시 자원을 사용합니다. 실제 사용자 DB에 시험 도서를 생성하거나 백업을 덮어쓰지 않았습니다.

알라딘 실제 검색·표지 다운로드·등록은 별도 임시 DB에서 확인했습니다. 전체 E2E의 알라딘 API·중고 HTML 응답은 프로세스 전용 fixture입니다. 따라서 실제 알라딘 전체 재고 갱신, 원격 배포, Docker 이미지 발행을 완료했다고 볼 수 없습니다. Java 소스는 수정하지 않았으며 기존 Spring·Docker 전체 검사를 이번 변경에서 다시 실행하지 않았습니다.

현재 로컬 개발 환경은 웹만 실행 중이며 재고 워커가 없었습니다. 사용자 DB를 읽기 전용으로 확인한 결과 도서 1,200개·권 4,281개, `quick_check=ok`, 외래키 위반 0건, 재고 작업 `IDLE`입니다. 워커가 없으면 재고 갱신·ZIP 복원은 대기합니다. 같은 `next/` 디렉터리에서 별도 터미널로 실행합니다.

```bash
npm run worker:dev
```

## 재현 명령

`next/`에서 실행합니다. 실행 중인 개발 서버가 있다면 빌드·E2E는 소스 사본에서 실행합니다. 테스트 포트는 `25648`입니다.

```bash
npm run verify:source
npm run build
npm run test:e2e
BOOKSHELF_E2E_SIGNUP=true npm run test:e2e
```

추가 회귀 검사는 `tests/integration/feature-parity.test.ts`, `tests/unit/remote-cover.test.ts`, `tests/e2e/feature-parity.spec.ts`, `tests/e2e/signup.spec.ts`에 있습니다. 가입 검사는 비어 있는 별도 임시 DB와 활성 가입 설정으로 실행하며 실제 회원가입 설정을 변경하지 않습니다. 브라우저 스크린샷은 `test-results/feature-parity-*/`에 생성됩니다.
