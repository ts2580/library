# 인증·표지 백업·재고 화면 리뷰 수정

2026-10-19, canary `c94801fdf4a10fe28c8346d9dced22e4ff8f26da` 기준 외부 리뷰 R1~R6의 수정 기록입니다. 운영 데이터와 외부 알라딘 서비스를 사용하지 않고 전용 임시 DB·표지·API fixture로 검증했습니다.

## 수정한 동작

| 리뷰 | 수정 |
| --- | --- |
| R1 | 비동기 암호 검증·해시 계산 뒤, SQLite 쓰기 트랜잭션에서 검증 당시 해시가 여전히 유효한지 재확인합니다. 레거시 승격 또는 비밀번호 변경, 기존 세션 폐기, 새 세션 발급을 같은 트랜잭션에서 처리합니다. 경합으로 해시가 달라졌으면 재시도를 안내하며, 새 세션 INSERT 실패 시 해시와 폐기도 롤백합니다. |
| R2 | 신규·변경 비밀번호에 UTF-8 72바이트 제한을 적용하고 해시 함수에서도 검사합니다. 기존의 긴 SHA-256 비밀번호는 전체 문자열 검증을 유지하고 자동 BCrypt 승격을 보류합니다. |
| R3 | 표지 참조의 SHA-256을 ZIP 항목 경로에 포함한 v3 형식을 사용합니다. manifest를 읽어 현재 계정의 DB 참조에만 복원하며, 빈 DB 또는 다른 계정의 XLSX 복원에서도 원본 경로별 표지를 구분합니다. |
| R4 | 복원 파일을 같은 디렉터리의 임시 경로에 쓰고 전체 이미지 디코딩을 확인한 뒤, 하드 링크로 최종 경로에 원자적으로 공개합니다. 실패 시 임시 파일을 정리하고, 기존 손상 파일은 재복원하며 정상 파일은 보존합니다. 생성 여부도 이미지 유효성으로 판단합니다. |
| R5 | 권 수정 시 레거시 재고 연결의 두 권차 비교를 NULL 안전 비교로 맞췄습니다. 유일한 NULL 권차만 연결하며 0권과 중복 NULL 권차를 구분합니다. |
| R6 | 책 상세는 비활성 상태에서도 기본 10초 간격으로 확인하고 탭 복귀 시 즉시 조회합니다. 실행 ID로 조회 사이에 완료된 작업도 감지합니다. 새 서버 prop은 최신 API 조회를 유도하며 이전 prop으로 진행 상태를 덮지 않습니다. GET 10초·POST 15초 제한, 재시도, 권한/삭제 오류 시 중단을 적용합니다. |

## 호환성과 업데이트

- DB bootstrap 버전 3은 `stock_refresh_job.run_id`만 추가합니다. 버전 1·2에서의 업그레이드와 반복 실행을 검사했으며, 기존 사용자 역할·재고·레거시 연결을 다시 이관하지 않습니다. 기존 자동 DB 백업 절차를 사용합니다.
- 웹과 워커는 같은 코드로 함께 업데이트합니다. v3 ZIP은 새 복원기가 필요합니다. 기존 v2 manifest 및 manifest 없는 ZIP도 지원하며, 구분할 수 없는 v2 파일명 충돌은 추정하여 덮어쓰지 않습니다. 이미 과거 ZIP에서 누락된 파일 자체를 복구할 수는 없습니다.
- 다른 계정이나 빈 DB에 가져오는 표지는 `cover://현재계정/imports/원본참조해시/파일명`으로 매핑합니다. 기존에 현재 계정이 소유한 참조는 유지합니다.
- 기존 BCrypt 해시에는 원문 길이가 없습니다. 이미 72바이트 이후가 잘려 저장된 비밀번호의 구분을 복구할 수는 없으며, 해당 계정은 새 규칙으로 비밀번호를 변경해야 합니다. 기존 BCrypt 로그인 호환은 유지합니다.
- 워커 잠금은 DB당 하나이며, 원자적 파일 공개는 동일한 로컬 파일시스템의 하드 링크를 사용합니다. 재고 갱신 시작 시 기존 재고를 비우는 정책과 APPEND_BOOK의 기존 가격 보존 정책은 유지합니다.

## PR #35 후속 리뷰 수정

위 검증은 최초 PR head `b66020e`의 기록입니다. 해당 head에 남은 리뷰 3건을 다음과 같이 수정했습니다.

- ZIP 중앙 디렉터리 전체를 배열로 만드는 `Open.file()`을 제거했습니다. 1차 스트리밍 검사에서 50,001번째 항목을 읽는 즉시 중단하고, 개별 파일 25MiB·전체 압축 해제 2GiB 제한을 적용합니다. 보관하는 항목 이름은 고정 크기 SHA-256으로 바꿨습니다. 2차 스트리밍에서 복원하므로 끝에 manifest가 있는 v2 ZIP도 읽습니다.
- v2/v3 manifest가 현재 계정의 표지로 선언한 파일이 ZIP에 없으면 실패 처리합니다. 기존 최종 표지가 이미 정상인 경우만 누락을 허용하며, 항목은 존재하지만 지원하지 않는 이미지인 경우에도 완료로 처리하지 않습니다.
- 전역 작업 행과 별도로 `stock_refresh_completion`에 계정별 마지막 완료 ID를 남깁니다. 성공·실패·중단 복구·명시적 재고 삭제와 같은 트랜잭션에서 갱신하며, 다음 계정의 작업이 진행되거나 끝나도 요청 계정 자신의 완료 ID만 응답합니다. 책 상세는 이 ID가 바뀌면 재조회합니다.
- DB bootstrap 버전 4는 위 테이블을 추가하고 현재 전역 행의 마지막 종료 작업을 이관합니다. 버전 1·2·3 업그레이드, 반복 실행, 기존 역할·재고·연결 보존을 검사했습니다.

후속 소스 검증: 문법·구조·타입 검사 및 단위·통합 **228개 통과**. 6만 항목 ZIP을 실제로 읽어 50,001번째에서 조기 종료하는 검사, manifest 누락/정상 기존 표지/지원하지 않는 이미지 검사, 계정별 완료 ID의 성공·실패·중단 복구·작업 소유권 상실 검사를 포함합니다.
