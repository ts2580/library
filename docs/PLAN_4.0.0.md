## 1. 확인한 근거와 한계

[공식 종료 공지](https://blog.aladin.co.kr/openapi/17486624)에 따라 기존 도서 검색·도서정보 OpenAPI가 2026-10-30 종료됐다. [이용 안내](https://blog.aladin.co.kr/openapi/5353304)에도 신규 키·프리미엄 신청 종료가 명시돼 있다.

2026-11-02 이 작업 환경에서 읽기 전용 HTTP 요청으로 확인한 결과다. 인증키·쿠키는 증거에 저장하지 않는다.

| 경로 | 입력·관측 결과 | 판단 |
|---|---|---|
| `/ttb/api/ItemSearch.aspx` | 기존 키로 `해리 포터` 검색, HTTP 200 / `text/xml`, 오류 코드 999 및 서비스 종료 메시지 | 기존 `response.json()` 경로로 사용 불가 |
| `/search/wsearchresult.aspx` | `SearchTarget=Book`, `SearchWord=해리 포터`, HTTP 200 | 제목·저자·출간월·가격·상품 링크·표지 추출 가능 |
| 동일 검색 경로 | `SearchWord=9788983928207` | 해당 도서 검색 가능; 광고·추가 영역을 제외한 결과 구분 필요 |
| `/shop/wproduct.aspx?ItemId=253997222` | `og:barcode`, `og:image`, `og:description` 등 | ISBN13·500px 표지·소개 요약 확인; 전체 소개문 확보는 미검증 |
| 검색 경로의 `SearchTarget=UsedStore` | `해리 포터` 검색, 결과 박스 25개; 첫 상품 ItemId 208556에 지점명·OffCode·링크 표시 | 보유 매장 목록 획득 가능성 확인 |
| `/usedstore/wproduct.aspx?ItemId=208556&OffCode=Geondae` | 4,600원 / 1부 / 상태 중 / 서가 E32, 구매 링크 | 개별 지점 상세 파싱 가능성 확인 |

이는 샘플의 실응답 확인이며 전체 기능의 `VERIFIED_REMOTE` 완료가 아니다. 동일 ISBN의 매장 재고 경로, 온라인 직배송, 모든 검색 옵션, 전체 페이지 순회, 다른 판본·ISBN10·재고 없음, 장시간 운용과 PC·모바일 UI는 미검증이다. 첫 ISBN의 중고매장 검색에서는 결과 박스가 없었으며, 이것만으로 확정 재고 0을 판정하지 않는다.

## 2. 구현 범위와 유지할 계약

공통 HTML 수집·파서를 `features/aladin/`에 두고 기존 `searchAladinBooks`·`lookupUsedStocks`의 호출 경계를 우선 유지한다. 새 공급자 프레임워크나 별도 크롤링 서비스는 만들지 않는다. HTML 요청은 서버에서 수행한다.

| 영역 | 현재 경로·대상 | 4.0.0 작업 |
|---|---|---|
| 수집·오류 처리 | `features/aladin/client.ts` | OpenAPI JSON 호출 제거, 검색·상품·지점 페이지 수집과 콘텐츠 검증 |
| 검색·정보·재고 정규화 | `features/aladin/service.ts`, `types.ts`, `validation.ts` | HTML 파서 분리, 검색 옵션 대응, ISBN 확인, 재고 결과 의미 명시 |
| 검색 UI·API | `app/(app)/aladin/`, `app/api/aladin/search/`, `components/books/aladin-*` | 키 검사 제거, 지원 옵션·오류·빈 결과 표시, 검색 상태 복원 |
| 등록 | `features/aladin/import.ts`, `bulk-import.ts`, `features/books/manual-create.ts` | 선택 항목 재검증·중복 처리·권차·외전·표지 저장 유지 |
| 정보 보강 | `features/books/enrichment.ts`, `enrichment-job.ts` | 빈 저자·설명·링크만 보강, 조회 중 사용자 수정 보호 |
| 재고 작업 | `features/inventory/service.ts`, `refresh-log.ts`, 워커 | 조회 실패 시 보존, 취소·재시도·계정 격리·작업 잠금 유지 |
| 표지 | `features/aladin/covers.ts`, `features/covers/regeneration.ts` | 직접 API 호출 잔존 제거, 도달 가능한 내부 호출 확인, 안전한 다운로드 유지 |
| 설정·검증 | `lib/env.ts`, `.env.example`, `tests/fixtures/mock-aladin.mjs` | 키 의존 제거, HTML fixture 전환, 문서 정렬 |

기존 도서·권·표지·재고·계정·백업 데이터는 보존한다. 표지 재생성 및 전체 정보 보강의 CA 임시 메뉴를 다시 노출하지 않는다. DB 스키마는 현행 6 유지가 기본이며, 공통 요청 조율을 위해 저장 구조가 필요하면 별도 마이그레이션·복원 검증을 계획에 추가한다.

### 검색 옵션 대응표

P0에서 다음 각 옵션을 실제 페이지 파라미터·반환값에 대응시키고 지원 여부를 기록한다. 비슷한 이름만 보고 같은 의미로 매핑하지 않는다.

- 검색 방식: `Title`, `Keyword`, `Author`, `Publisher`
- 검색 대상: `Book`, `Foreign`, `Music`, `DVD`, `Used`, `eBook`, `All`
- 정렬: `PublishTime`, `Accuracy`, `Title`, `SalesPoint`, `CustomerRating`, `MyReviewCount`
- 분류·출간 기간·품절 제외·표지 크기·페이지당 개수·페이지 번호

검색 총 건수와 다음 페이지 유무를 실제 응답에서 확인한다. 실제 개수와 다른 값을 만들어 기존 페이지 UI를 유지하지 않는다. 지원 불가능한 옵션은 UI에서 숨기거나 비활성화하고 서버에서도 명시적으로 거절한다. 주요 옵션 제거가 필요하면 변경 범위를 검토한 뒤 계획·출시 안내에 기록한다.

## 3. 단계별 작업과 완료 기준

아래는 최초 계획의 단계별 완료 기준이다. P0~P5의 로컬 구현·검증·출시 준비 문서 작업을 마쳤으며, 실제 원격 확인 범위와 한계는 작업 기록을 따른다. 로컬 구현·회귀 검증 통과 시 `IMPLEMENTED_LOCAL`, 해당 범위의 실제 원격 확인 시 `VERIFIED_REMOTE`를 각각 기록한다. `DEPLOYED`는 운영 교체와 점검 완료 시에만 기록한다.

### P0. 응답 표본과 지원 범위 확정

- 일반 검색, ISBN10/13, 판본이 다른 동명 도서, 검색 없음, 마지막·다음 페이지, 직배송과 매장 재고의 최소 표본 수집.
- 상품 식별자와 유효 ISBN 분리. 검색 HTML의 `K...` 상품 코드를 ISBN10으로 취급하지 않음.
- 검색 결과·광고 영역 구분, 출간일 정밀도, 소개 요약/전체 본문 제공 여부, 중고 상품의 지점·판매자 구분 확인.
- 필요 최소 HTML을 fixture로 저장하고 수집 날짜·원본 URL·기대 필드 기록. 키·세션·개인정보 제거.
- 완료 기준: 옵션 대응표, 필드 제공 여부, 직배송·매장 조회 경로, 명시적 빈 결과 및 오류 구분 근거 확보.
- 막힘 처리: 직배송이나 판본 확인 실패를 매장 조회 성공으로 대체하지 않음. 해당 항목을 미검증으로 남기고 출시 범위 확정 전 해결.

### P1. HTML 수집과 정규화 계층

- 호스트·프로토콜·리다이렉트 검증, 타임아웃·응답 크기 제한, HTML 형식 및 정상 페이지 구조 확인.
- 200 오류 페이지·점검·접근 제한·구조 변경을 정상 빈 결과와 구분. 차단 시 우회 반복 없이 오류와 재시도 가능 시점을 전달.
- 기존 100ms API 간격을 그대로 승계하지 않음. 초기 계획은 호스트당 동시 요청 1개·최소 간격 1초이며 소량 검증으로 조정 근거 기록.
- 웹·워커가 별도 프로세스임을 고려해 요청 간격·429 cooldown을 공유하는 방식 결정. 프로세스별 제한만으로 전체 제한을 충족했다고 판단하지 않음.
- 동일 요청 병합 및 크기 제한 캐시 적용. 초기 TTL 후보: 검색 5분, 상품 정보 24시간, 재고 30초. 재고 명시 갱신은 캐시를 건너뛰고, 실패 응답은 정상값으로 캐시하지 않음.
- 429의 `Retry-After`와 일시적 네트워크/5xx에 제한적 재시도. 파싱 실패·서비스 종료·접근 거부에 반복 재시도하지 않음.
- 완료 기준: HTML fixture 기반 필드 추출·오류 분류 테스트와 웹/워커 공통 호출 제한 검증 통과.

### P2. 검색·등록·정보 보강 전환

- 검색 목록은 목록 응답만 우선 사용하고, ISBN·소개 등 상세 정보는 필요한 항목만 조회·캐시하여 페이지마다 무조건 N개 상세 요청하지 않음.
- ISBN 정규화와 판본 일치 확인. 잘못된 판본의 표지·구매 링크가 저장되지 않도록 등록과 보강 경계에서 검증.
- 출간일은 실제 확인한 정밀도로 저장·정렬. 일자가 없는 데이터를 임의 날짜로 확정하지 않고 기존 권차 정렬과의 호환 규칙·테스트 추가.
- 직접 체크 순서, 전체 선택의 출간일·숫자 순서, 외전, 최대 10개 선택 페이지, 서버 재조회, 검색어·페이지·기존 책 선택 유지.
- 소개 요약만 제공되면 전체 소개라고 표시하지 않음. 수동 입력·기존 값과 조회 도중 수정한 값은 보존.
- 검색·수동 추가·보강·재고 시작의 모든 키 검사 제거. 기존 `.env`의 키는 무시 가능하도록 하고 사용자의 파일을 자동 수정하지 않음.
- 완료 기준: 키 없는 환경에서 검색→미리보기→새 책/기존 책 등록→정보 보강과 표지 저장 통과; 관련 단위·통합 테스트 통과.

### P3. 직배송·매장 재고 및 갱신 정책 전환

- ISBN으로 정확한 상품을 식별한 뒤 전체 중고 목록(`TabType=0`)에서 직배송·우주점의 등급·가격·구매 링크를 정규화. 모든 페이지를 조회하며 개인·전문 판매자는 제외. 2026-11-03 사용자 요청으로 방문 구매 재고 대신 해당 목록의 온라인 판매 상품 기준으로 변경.
- 온라인 중고에서 알라딘 직배송과 개인 판매자를 분리. `all`, `dropshipping`, `offstore` 각각의 결과와 중복 규칙 검증.
- 동일 지점의 여러 상품·등급·수량을 구분. 기존 행 수가 실제 부수와 같은지 확인하고 집계 의미를 유지하거나 변경을 명시.
- 현재 `REPLACE_ALL`은 조회 전에 계정 재고를 삭제함. 이를 제거하고 **완전히 검증된 권의 결과만 트랜잭션으로 교체**하도록 변경.
- 성공한 명시적 재고 0은 해당 권의 기존 재고 제거, 실패·부분 실패·파싱 실패는 해당 권의 기존 재고 보존. 보존된 이전 조회 결과는 최신 확인값과 구분해 표시.
- 구매 완료·구매 불필요·삭제된 권의 정리 범위는 해당 계정의 현재 상태로 판단하고, 원격 조회 실패와 별개로 검증. 전체 삭제는 기존 명시적 사용자 작업으로 유지.
- 취소/재시작/작업 교체 이후 늦게 도착한 결과의 저장 차단. `APPEND_BOOK`의 기존 가격 유지와 `REFRESH_SELECTED`의 대상 제한 유지.
- 완료 기준: 한 권 실패·한 지점 실패·전체 장애·정상 빈 결과·취소·동시 작업 시 데이터 보존/교체 범위와 집계·로그·실패 재시도 검증 통과.

### P4. 실제 사용 흐름과 회귀 검증

- 기존 JSON API fixture와 mock을 HTML 수집 경계에 맞게 교체. 성공 응답만 바꿔 테스트를 통과시키지 않고 종료 XML·빈 결과·깨진 HTML·차단·429·타임아웃 사례 추가.
- 변경 영역의 단위·통합 테스트 → `npm run verify:source` → `npm run build` → PC·모바일 Playwright 순으로 검증.
- PC·모바일에서 검색 필터·페이지 이동·새 책/기존 책 등록·권차·외전·돌아가기 상태·표지 확대·토스트·재고 갱신/취소/재시도 확인.
- fixture 기반 전체 E2E와 별도로 소량의 실제 알라딘 요청 검증. 날짜·ISBN/ItemId·요청 수·응답 상태·추출 필드·첫 실패를 기록. 외부 응답을 사용하는 쓰기 검증은 임시 계정·DB에서 수행.
- Docker 웹·워커 이미지 검증과 기존 DB 사본 업그레이드·백업/복원 검증. 실제 운영 DB에 `db:verify` 등 bootstrap 가능한 명령을 검증 목적으로 실행하지 않음.
- 완료 기준: 지원 범위별 로컬/원격 증거와 PC·모바일 결과 확보. 외부 장애로 원격 검증이 막히면 로컬 완료와 구분하고 정식 출시 완료로 처리하지 않음.

### P5. 4.0.0 출시 준비

- `.env.example`, README, 이전 안내, 아키텍처, 검증·기능 대조 문서 갱신. 런타임의 `ttb/api` 호출과 키 의존이 남지 않았는지 확인.
- 구현 완료 후 `RELEASE_4.0.0.md` 작성: 지원/제외 기능, 조회 실패·재고 보존 동작, 웹·워커 동시 교체, 데이터/설정 호환, 검증 근거 명시.
- DB 사본과 표지 백업으로 롤백 절차 검증. 3.5.1로 되돌려도 종료된 알라딘 API 기능은 복구되지 않음을 안내.
- 패키지·lockfile·Compose·문서의 4.0.0 정렬 재확인. canary/main 반영, 태그, GitHub Release, 이미지 발행, 운영 배포를 별도 단계로 기록.
- 완료 기준: P0~P4의 필수 범위 통과와 출시 문서 확정. 현재 버전 표기 변경은 이 조건 충족이나 발행을 의미하지 않음.

## 4. 실행 순서와 범위 밖

실행 순서는 **P0 → P1 → P2 → P3 → P4 → P5**다. P0의 직배송·ISBN/판본·검색 옵션 결과로 후속 범위를 구체화한다. 검증되지 않은 필드나 페이지를 추정해 구현 완료로 기록하지 않는다.

이번 계획에서 새 검색 공급자 추가, UI 전면 재설계, 기존 데이터 일괄 재수집, 과거 권차 자동 수정은 제외한다. 버전 상향과 계획 작성은 로컬 변경으로 끝내며 커밋·푸시·발행·운영 교체는 포함하지 않는다.
