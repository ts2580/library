2026-11-02 KST, 사용자 요청으로 작업 재개. 아래 최신 결과는 최초 중단 당시 기록보다 우선한다.

## 2026-11-03 재고 10권 병렬 처리

사용자 추가 요청으로 재고 갱신을 최대 10권 동시 처리로 변경. 아래 이전 검증보다 이 절의 소스 검증이 최신이다.

- 고정 10개 처리 슬롯을 두고 권 하나가 끝날 때마다 다음 권을 시작. 한 권의 목록 페이지는 계속 순차 조회. 완료 순서와 관계없이 처리·성공·빈 재고·실패 수를 한 번씩 집계.
- 웹·워커 합산 HTTP 동시 실행도 최대 10건. 기존 기본 시작 간격 1초와 429 cooldown을 유지하면서 응답 대기를 겹침. 요청 시작 시점만 짧게 잠그고, 응답 본문을 다 받을 때까지 슬롯 파일 잠금을 유지.
- `aladin-requests.sqlite.slot-0`~`.slot-9`를 사용하며 프로세스 종료 시 OS가 슬롯 해제. 시간 만료로 살아 있는 요청을 중복 허용하지 않음. 실행 중 상태·슬롯 파일 삭제 금지. 웹·워커를 같은 소스로 함께 재시작해야 함.
- 동시 성공 응답이 다른 요청의 cooldown을 지우지 않도록 MAX 갱신. 시작 간격 대기와 잠금 경합을 분리하여 60초 간격에서 여러 요청을 기다려도 정상 대기가 120초 잠금 실패로 처리되지 않음.
- 취소·작업 교체 후 저장 차단, 호출 제한 시 다음 권 배정 중단. 이미 진행 중인 조회가 모두 끝난 뒤 작업 종료 처리. 취소 시 HTTP 자체를 강제로 끊는 방식은 아님.
- 검증: 소스 **394개 테스트**, 구문·구조·타입 검사 및 프로덕션 빌드 통과. 25권 슬롯 재충원/역순 완료 집계, 10개 진행 중 취소, 429 이후 미시작 권 보존, 실제 자식 프로세스의 공유 슬롯·시작 간격·강제 종료 후 슬롯 회수 검증 포함.
- PC·모바일 웹/워커 연동 E2E **14개 통과**(통합 수집·작업 로그·개별/선택 재시도·직접 검색·취소). 외부 통신은 격리 HTML fixture 사용.
- 근거: `temp/aladin-parallel/source-final.log`, `build.log`, `targeted-final.log`, `browser.log`. 병렬 설정으로 실제 알라딘 부하 시험·Docker 재빌드·발행·운영 배포는 수행하지 않음.

## 리뷰 후속 수정

아래 초기 완료 검증 이후 P2 세 건 수정. 이 절은 해당 리뷰 수정 시점의 소스 상태이며, 아래 Docker 이미지·실응답 및 전체 E2E 수치는 리뷰 수정 전 스냅샷의 결과다.

- 대량 선택의 상품 상세 조회를 순차 실행하여 같은 등록 요청이 요청 조율 잠금의 120초 대기 한도를 소진하지 않도록 수정. 가상 시간과 실제 SQLite 잠금으로 150권의 수정 전 `SQLITE_BUSY` 재현, 수정 후 전체 등록 및 권차 유지 확인. 상세 조회 중 실패 시 후속 요청 중단과 저장 0건 확인.
- K/U 코드만 있는 ISBN 검색 후보를 상세 조회한 뒤 ISBN 비교. ISBN10/13 정규화 비교 및 다른 판본 거절, 기존 수동 설명·저자 보존 확인.
- 요청 조율 sidecar의 `cooldown_until`을 정상 요청 간격과 분리. 30,001ms·60,000ms 정상 대기, 긴 429 cooldown, 짧은 cooldown보다 긴 정상 간격 검증. 기존 `next_at`은 보존하고 현재 설정 간격을 초과한 기존 대기는 보수적으로 cooldown으로 이전. 앱 DB 스키마 변경 없음.
- 최신 소스 검사: 33개 파일 **371개 테스트** 및 구문·구조·타입 검사 통과. 프로덕션 빌드 통과. 변경 경로의 PC·모바일 E2E **12개 통과**.

## 구현한 내용

1. `features/aladin/client.ts`: 기존 OpenAPI 호출 제거, 공개 HTML 요청으로 전환. URL/리다이렉트·응답 형식·크기 제한, 타임아웃, 제한적 재시도, 429 cooldown 처리.
2. `request-gate.ts`: 별도 SQLite 파일로 웹·워커 간 요청 직렬화. 기본 간격 1초. 앱 데이터 DB 스키마는 변경하지 않음.
3. `html.ts`·`service.ts`: 검색·상품 정보·직배송·매장 검색·지점 상세 파싱, 검색/상품 캐시, 상품 판본 확인.
4. `item-key.ts`: 선택 키와 ISBN 분리. K 코드 등은 ISBN에 저장하지 않고 상품 ID로 선택 후 상세 정보 확인.
5. 등록·정보 보강·표지 경로 및 UI/API의 인증키 검사 제거. 빈 값만 보강하는 기존 계약 유지. `.env.example`에는 `ALADIN_PAGE_INTERVAL_MS=1000` 사용.
6. 전체 재고 갱신의 선삭제 제거. 완전히 확인한 권만 교체하고 정상 빈 결과만 비움. 실패·부분 실패는 이전 재고 보존, 구매 완료 등 로컬에서 확정된 불필요 재고는 정리.
7. 재고 목록에 저장 시각과 최근 조회 실패 여부 표시. 재고 조회의 기존 원본 JSON 영역은 매장 등급별 최저가/직배송 상품별 가격 설명으로 변경.
8. HTML fixture와 파서·전송·프로세스 간 제한·재고 보존 테스트 추가. 선택 키·검색 옵션·ISBN10 fixture 전환 진행.

## 미해결 사항과 재개 순서

1. **직배송 0건에서 페이지 종료 처리 수정.** 실제 빈 목록은 `.nright_text`가 `0페이지`다. `parseUsedPage`가 pages=0을 반환하지만 `usedOffers`는 page=1부터 `page === current.pages`로 종료하므로, 빈 결과가 계속되면 다음 페이지를 반복 요청한다. 실응답 검증은 40회 예산 이후 41번째 시도에서 중단됨. 예산을 늘리지 말고 명시적 0건 즉시 종료와 0페이지 fixture 회귀 테스트를 먼저 추가해야 함. 현재 미수정.
2. **브라우저 실패 4건 정리.** 2건은 ISBN10을 처리하지 않던 새 E2E fixture 때문에 발생. fixture에 ISBN10→13 정규화를 추가했으나 재실행 전 중단. 나머지 2건은 테스트가 기존 `ItemId=fixture-1-1`을 기대하지만 새 fixture는 숫자 상품 ID를 사용하는 불일치. 해당 기대값은 아직 수정하지 않음.
3. **검증 실행 분리.** 첫 선택 E2E 실행 중 재빌드가 겹친 구간이 있어 실행을 중단함. 수정한 fixture·UI를 반영한 빌드가 끝난 상태에서 실패 사례부터 재검증하고 PC·모바일 전체 검사 진행. 중단된 실행을 최종 검증으로 사용하지 않음.
4. **실제 응답·브라우저 완료 확인.** 마지막 0건 사례부터 확인하고 요청 수를 기록. fixture E2E와 실제 알라딘을 사용하는 브라우저 흐름을 구분. 실제 웹 UI→등록→보강→재고의 전체 흐름은 임시 DB로 추가 검증 필요.
5. **Docker/데이터 호환 검증 및 문서 정리.** 최종 소스로 이미지 재빌드 후 웹·워커 smoke, DB 사본과 백업 복원/롤백 검증. `RELEASE_4.0.0.md`, 아키텍처·검증·기능 대조 문서와 계획 상태 갱신은 아직 남아 있음.
