# Bookshelf 4.0.0

알라딘 OpenAPI 종료에 따른 공개 검색·상품·중고매장 페이지 연동 전환. API 키 없이 도서 검색·선택 등록·정보 보강·재고 조회를 수행하며, 조회 실패 시 기존 재고를 보존하도록 변경.

4.0.0은 [GitHub Release](https://github.com/ts2580/library/releases/tag/v4.0.0) 및 Docker Hub에 정식 발행 완료. 아래 내용은 출시 준비 중 기록한 변경 사항과 검증 이력이며, 최종 소스·이미지 digest와 발행 증적은 해당 Release 참고. 후속 패치는 [4.0.1 변경 내용](RELEASE_4.0.1.md) 참고.

## 변경 내용

- 서버의 `ttb/api` 호출과 `ALADIN_TTB_KEY` 의존 제거. 기존 `.env` 키는 무시하며 자동 수정하지 않음.
- 공개 검색 HTML의 실제 건수·페이지 크기로 페이지 이동 처리. 광고·추천 영역 제외, 비정상 페이지와 정상 빈 검색 결과 구분.
- 상품 ID로 선택 항목 식별. K/U 코드와 ISBN 분리, 상세 상품의 ISBN 확인 후 등록. 직접 체크 순서, 일괄 선택의 출간일·숫자 순서, 외전 처리 유지.
- 등록 시 필요한 상품만 상세 조회하고 표지 다운로드. 소개는 제공되는 요약만 저장하며, 요약이 없는 상품은 빈 값 유지. 검색 페이지에 출간월만 있으면 월 정밀도 유지.
- 외국 도서를 포함하도록 정보 보강의 검색 대상을 전체로 지정. 직접 입력한 저자·설명 및 조회 중 수정한 값 보존.
- 전체 중고 목록에서 직배송·이 광활한 우주점의 상품별 가격과 구매 링크를 수집. 개인·전문 판매자 제외. 매장별 추가 요청 없이 목록의 모든 페이지를 조회. 표시 건수는 온라인 판매 목록 행 수이며 매장 실물 부수와 다를 수 있음.
- 전체 갱신의 선삭제 제거. 완전히 확인한 권만 교체하고, 명시적 재고 0건만 해당 권의 기존 재고 삭제. 부분 실패·차단·파싱 실패 시 기존 재고 유지. 저장 시각과 최근 조회 실패 여부 표시.
- 직배송 0건의 `0페이지` 응답에서 즉시 종료하도록 수정. 취소·재시작 이후 늦게 도착한 결과의 저장 차단, 실패 건 재시도, 계정별 격리 유지.

## 검색 옵션과 외부 페이지의 한계

2026-11-02 공개 페이지의 컨트롤 및 소량 실응답 기준. 옵션의 모든 조합과 모든 상품군의 메타데이터 완전성을 보장하는 의미는 아님.

| 기존 옵션 | 공개 페이지 대응 |
|---|---|
| 제목 / 키워드 / 저자 / 출판사 | `KeyTitle` / `SearchWord` / `KeyAuthor` / `KeyPublisher` |
| 국내 / 외국 / 음반 / DVD / 중고 / 전자책 / 전체 | `Book` / `Foreign` / `Music` / `DVD` / `Used` / `EBook` / `All` |
| 출간일 / 정확도 / 제목 / 판매량 / 평점 / 리뷰 수 | `SortOrder=5/11/1/2/3/4`, 공개 페이지의 정렬 링크와 대조 |
| 카테고리 / 출간 기간 / 품절 제외 | `CategorySearch` / `KeyRecentPublish` / `OutStock=1` |
| 결과 개수 / 페이지 | `ViewRowCount` / `page`, 응답에서 확인한 실제 페이지 크기 사용 |
| 표지 크기 | 크게 500px, 중간 150px, 작게 축소 이미지, 없음은 다운로드 생략 |

공개 페이지의 `OutStock=1`은 미출간·품절·절판을 함께 제외함. 검색 필터와 정렬은 알라딘의 공개 페이지 의미를 따름. 전체 소개 본문, 개인 판매자 재고, 목록에 없는 방문 구매 전용 재고·매장 실물 부수는 제공 범위 밖. 공개 페이지 구조가 바뀌거나 접근이 제한되면 오류를 표시하며 빈 재고로 간주하지 않음.

## 기존 설치와 데이터 호환

앱 DB 스키마 7에 작업별 재고 갱신 기록(`stock_refresh_run`) 추가. 갱신 1회당 총 권수·시작/종료시간·작업시간 표시. 직전 실행 정보는 가져오며, 그보다 오래된 권별 로그에서 정확한 시작/종료시간을 추정하지 않음. 미해결 실패만 권 단위로 표시하고 재조회 성공 시 해제. 기존 권별 로그는 마이그레이션에서 삭제하지 않음. 책·권·표지·재고·계정·Excel/표지 ZIP 백업 형식 유지. 전체 정보 보강과 표지 재생성의 임시 프로필 메뉴는 계속 숨김.

재고 갱신은 최대 10권을 병렬 처리하며 빈자리가 나면 다음 권을 시작. 웹·워커 합산 HTTP 요청도 최대 10건이고, 시작 간격은 `ALADIN_PAGE_INTERVAL_MS=1000` 기본값 유지. 동일한 로컬 `/data`의 `aladin-requests.sqlite`에 간격·429 대기 시점, 인접 `.slot-0`~`.slot-9` 파일 잠금으로 동시 실행 수 관리. 실행 중 이 파일들을 삭제하지 않음. 재고는 매번 새로 조회하며 검색 5분·상품 24시간 캐시는 프로세스별로 제한된 크기로 유지.

기존 설정과 데이터 볼륨을 유지해 **웹·워커를 함께 교체**. 발행 이미지와 최종 검증 대상은 4.0.0 GitHub Release 및 부속 증적 참고.

## 백업 및 롤백

1. 웹·워커를 중지하고 활성 DB와 표지 디렉터리를 같은 시점으로 백업. 실행 중 DB 사본은 SQLite online backup을 사용하며 WAL이 있는 원본 파일만 단독 복사하지 않음.
2. 4.0.0을 별도 데이터 사본에 실행해 로그인·책/권·표지·재고 조회와 DB 무결성 확인.
3. 롤백 시 웹·워커를 모두 중지하고 3.5.1 이미지 및 백업 DB·표지를 함께 복원. 백업 이후 변경 사항은 별도 보존 필요.
4. 기존 스키마 5 사본의 6 이전, 3.5.1 소스의 부트스트랩·무결성 검사, DB/표지 ZIP 백업 복원 후 데이터 비교 수행. 운영 서비스 자체의 롤백 실행과는 구분.

3.5.1로 되돌려도 종료된 알라딘 OpenAPI 기능은 복구되지 않음.
